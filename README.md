# 🧾 网站建设合同生成器

一个面向网站建设项目的轻量级 HTML 合同生成工具。

项目采用 **单文件 HTML + 原生 JavaScript + LocalStorage + JSON 导入/导出** 的方式实现，无需服务器、无需数据库、无需安装依赖，直接打开即可使用。

适用于：

- WordPress 网站建设
- 企业官网
- 外贸网站
- 产品展示网站
- 品牌官网
- 个人 / 公司承接网站建设项目
- 其他需要明确“需求、工期、修改、验收、交付、售后”的网站项目

---

## 一、项目定位

这个项目的目标不是制作一份复杂、冗长的法律合同，而是解决网站建设过程中最常见、最容易发生争议的问题：

- 项目到底包含哪些内容
- 哪些内容不属于默认范围
- 客户后期新增需求如何处理
- 免费修改包含几轮
- 客户迟迟不提供资料时工期如何计算
- 网站如何验收
- 什么时候支付尾款
- 尾款未结清时是否交付源码和最高权限
- WordPress / Elementor / 插件 / 主题等第三方服务出现问题时责任如何划分
- 网站交付后哪些属于免费质保，哪些属于新增维护
- 微信、邮件等沟通记录是否可以作为确认依据

设计原则：

> **核心说清楚，合同不要面面俱到。**

当前版本将合同正文控制为 **9 个核心条款 + 1 个附件**，打印目标为 **A4 约 4～5 页**。

---

## 二、核心特点

### 1. 正文 + 附件分离

合同正文负责约定通用规则。

附件一负责记录具体项目内容，例如：

- 项目名称
- 网站域名
- 网站类型
- 建站系统
- 语言版本
- 参考网站
- 制作周期
- 免费修改次数
- 免费质保时间
- 合同金额
- 付款方式
- 页面 / 栏目清单
- 功能清单
- 资料录入
- 第三方费用
- 特别约定

这样以后更换客户或项目时，通常只需要修改附件内容，不需要重新改整份合同。

---

### 2. 支持个人 / 公司 / 其他组织

甲方和乙方均支持：

- 个人
- 公司
- 其他组织

字段包括：

- 主体类型
- 名称 / 姓名
- 证件 / 统一社会信用代码
- 联系人 / 负责人
- 电话
- 微信 / 其他联系方式
- 邮箱
- 地址

因此不会绑定“个人接单”这一身份，后期即使由个人升级为公司主体，也可以继续使用。

---

### 3. 项目范围清晰

合同以《附件一：项目需求与报价确认单》作为项目范围依据。

附件中未明确约定的内容，不默认包含。

例如：

- 新增页面
- 新增功能
- 新增语言
- 数据迁移
- 大量内容录入
- 专项 SEO
- 第三方接口
- 额外维护

都应重新确认。

---

### 4. 需求变更机制

对超出原项目范围的需求，建议先明确：

1. 变更内容
2. 新增费用
3. 工期影响

再通过微信、邮件或其他可留痕方式确认后实施。

避免出现：

> 客户随口提出一个需求，乙方做完后却无法确认费用。

---

### 5. 修改次数可控

默认支持可填写的免费修改轮次。

当前建议值：

```text
2 轮集中修改
```

“一轮修改”指甲方针对同一阶段成果一次性汇总提出的修改意见。

已确认的设计方案如果重新推翻、重新设计，或新增页面、功能、语言版本等，不再属于普通免费修改。

---

### 6. 工期自动排除等待时间

项目周期默认从以下条件满足后开始计算：

```text
首付款到账
+
甲方提供首批完整资料
```

以下时间不计入乙方制作周期：

- 等待甲方提供资料
- 等待甲方补充资料
- 等待设计确认
- 等待修改意见
- 第三方平台审核
- 域名解析等非乙方可控时间

---

### 7. 验收与尾款闭环

合同将核心流程统一为：

```text
开发完成
↓
测试 / 验收
↓
验收通过
或
视为验收通过
↓
支付尾款
↓
正式上线
↓
完整交付
```

默认约定：

- 首次验收：5 个工作日
- 修改后再次确认：3 个工作日
- 验收通过后：3 个工作日内支付尾款

在项目基本符合附件一约定的前提下，如果甲方：

- 长期不反馈
- 已绑定正式域名对外使用
- 已正式开展业务
- 已投放广告
- 已提交搜索引擎
- 已通过网站接收真实询盘

可视为项目已经进入实际使用状态。

---

### 8. 尾款与完整交付绑定

尾款结清后，根据项目实际情况完成交付：

- WordPress 管理员账号
- 网站文件 / 源码
- 数据库备份
- 域名管理权限
- 服务器权限
- 可转移的第三方账号或授权信息

尾款未结清前，可以只提供测试环境或受限访问。

---

### 9. 第三方服务边界

项目明确区分乙方开发内容和第三方服务。

常见第三方服务包括：

- WordPress
- Elementor
- 主题
- 插件
- 字体
- 图库
- API
- 域名
- 主机
- SSL
- CDN

第三方出现以下情况时，不默认视为乙方违约：

- 涨价
- 停止服务
- 停止维护
- API 改版
- 插件兼容性变化
- WordPress 大版本升级
- 主机服务商故障

---

### 10. SEO 不承诺结果

如果附件中包含“基础 SEO”，仅代表网站技术层面的基础配置。

例如：

- Title / Description
- Sitemap
- 基础可抓取结构
- 基础搜索引擎友好设置

不代表承诺：

- Google / 百度一定收录
- 关键词排名
- 网站流量
- 询盘数量
- 转化率

---

### 11. 免费质保边界清晰

默认免费技术质保：

```text
30 天
```

免费质保主要针对：

> 本合同范围内由乙方制作内容的程序性故障。

以下通常不属于免费质保：

- 新增页面
- 新增功能
- 内容更新
- SEO 运营
- 第三方插件升级
- 第三方服务故障
- 服务器环境变化
- 甲方自行修改代码
- 第三方修改网站
- 攻击或恶意破坏

---

### 12. 最终备份期限

默认约定：

```text
最终交付版本备份保留 30 天
```

超过期限后，乙方不再承担长期保存义务。

甲方应自行负责网站后续备份。

## 四、数据保存方式

本项目不需要数据库。

数据主要保存在：

```text
浏览器 LocalStorage
```

页面刷新后，当前填写内容仍然保留。

同时建议每个正式项目都单独导出一份 JSON 文件。

例如：

```text
WEB-2026-0928-01.json
WEB-2026-1005-01.json
WEB-2026-1012-02.json
```

JSON 文件可以再次导入，恢复合同数据。

## 五、导入 / 导出

### 导出

点击：

```text
导出 JSON
```

即可保存当前合同数据。

导出内容包含：

- 合同基本信息
- 甲方信息
- 乙方信息
- 项目信息
- 金额
- 周期
- 修改次数
- 验收参数
- 售后参数
- 页面 / 栏目数据
- 功能勾选状态
- 特别约定
- 附件确认信息

---

### 导入

点击：

```text
导入 JSON
```

选择之前由本工具导出的 JSON 文件，即可恢复对应合同。

建议：

> 每签署一个正式项目，都同时保留 HTML / PDF / JSON 三份文件。

---

## 六、打印与 PDF

点击：

```text
打印 / 保存 PDF
```

浏览器会进入打印模式。

推荐：

```text
纸张：A4
方向：纵向
缩放：默认 / 100%
页边距：默认或最小
背景图形：可关闭
页眉和页脚：关闭
```

合同设计目标：

```text
正文：约 3 页
附件一：约 1～2 页
总页数：尽量控制在 5 页以内
```

不同浏览器、打印机、字体环境可能导致少量分页差异。

## 十一、安全建议

### 建议

- 每个项目定期导出 JSON
- 正式合同保存 PDF
- 重要项目保留最终交付版本
- JSON / PDF 做本地和异地备份
- 私有部署时增加登录或访问控制
- 不要把真实身份证、客户信息提交到公开 GitHub 仓库

### 不建议

- 只依赖浏览器 LocalStorage
- 在公共电脑填写真实合同
- 将真实客户 JSON 提交到 GitHub
- 将客户账号、密码写入公开仓库

---

## 十二、设计原则

项目坚持以下原则：

### 1. 简单

优先使用原生：

```text
HTML + CSS + JavaScript
```

不为了功能增加技术复杂度。

### 2. 可维护

合同规则和项目数据分离。

正文尽量稳定，项目差异放在附件中。

### 3. 可长期使用

合同不绑定：

- 某个客户
- 某个公司
- 某个建站系统
- 某种主体身份

个人、公司、其他组织均可使用。

### 4. 聚焦真实风险

不是为了把合同写得越来越长，而是优先解决：

```text
范围
工期
修改
变更
验收
尾款
交付
第三方
售后
```

这些最常见的建站纠纷。
